6
Migrate Neon schema + data to Cloud SQL
Export from Neon via pg_dump, import via Cloud SQL Auth Proxy tunnel.
# Export from Neon
pg_dump "$NEON_POSTGRES_URL" \
  --no-owner --no-privileges \
  -f neon_dump.sql

# Open local tunnel to Cloud SQL (runs in background)
cloud-sql-proxy --port 5433 \
  $PROJECT_ID:$REGION:$SQL_INSTANCE &

# Import into Cloud SQL
psql "host=127.0.0.1 port=5433 dbname=mrd_producer user=app_user password=YOUR_PASSWORD" \
  -f neon_dump.sql

Populate Secret Manager

# Helper function
create_secret() {
  gcloud secrets create "$1" --replication-policy=automatic
  echo -n "$2" | gcloud secrets versions add "$1" --data-file=-
}

create_secret GOOGLE_API_KEY        "..."
create_secret GOOGLE_SEARCH_ENGINE_ID "..."
create_secret GOOGLE_CLIENT_ID      "..."
create_secret GOOGLE_CLIENT_SECRET  "..."
create_secret AUTH_SECRET           "..."
create_secret ANTHROPIC_API_KEY     "..."
create_secret OPENAI_API_KEY        "..."
create_secret ADMIN_EMAILS          "ori@compulocks.com"
create_secret ALLOWED_RD_EMAILS     "..."

# POSTGRES_URL uses Cloud SQL Unix socket — NOT the Neon TCP URL
create_secret POSTGRES_URL \
  "postgres://app_user:PASSWORD@/mrd_producer?host=/cloudsql/$PROJECT_ID:$REGION:$SQL_INSTANCE"

# Grant Cloud Run service account access to all secrets
SA="${PROJECT_NUMBER}-compute@developer.gserviceaccount.com"
for SECRET in GOOGLE_API_KEY GOOGLE_SEARCH_ENGINE_ID GOOGLE_CLIENT_ID \
              GOOGLE_CLIENT_SECRET AUTH_SECRET POSTGRES_URL \
              ANTHROPIC_API_KEY OPENAI_API_KEY ADMIN_EMAILS ALLOWED_RD_EMAILS; do
  gcloud secrets add-iam-policy-binding $SECRET \
    --member="serviceAccount:$SA" \
    --role="roles/secretmanager.secretAccessor"
done

# Also grant Cloud SQL access to Cloud Run service account
gcloud projects add-iam-policy-binding $PROJECT_ID \
  --member="serviceAccount:$SA" \
  --role="roles/cloudsql.client"
⚠ Critical: POSTGRES_URL must use the Unix socket path ?host=/cloudsql/PROJECT:REGION:INSTANCE — not the Neon TCP URL. Cloud Run routes this through the Auth Proxy automatically via --add-cloudsql-instances.
8
Set up Workload Identity Federation (GitHub Actions → GCP)
Keyless auth — no long-lived service account key stored in GitHub secrets.
# Create service account for GitHub Actions
gcloud iam service-accounts create github-actions-deploy \
  --project=$PROJECT_ID \
  --display-name="GitHub Actions Deploy"

# Grant roles
gcloud projects add-iam-policy-binding $PROJECT_ID \
  --member="serviceAccount:github-actions-deploy@$PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/run.admin"
gcloud projects add-iam-policy-binding $PROJECT_ID \
  --member="serviceAccount:github-actions-deploy@$PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/artifactregistry.writer"
gcloud projects add-iam-policy-binding $PROJECT_ID \
  --member="serviceAccount:github-actions-deploy@$PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/iam.serviceAccountUser"

# Create WIF pool + provider
gcloud iam workload-identity-pools create github-pool \
  --project=$PROJECT_ID --location=global \
  --display-name="GitHub Actions Pool"

gcloud iam workload-identity-pools providers create-oidc github-provider \
  --project=$PROJECT_ID --location=global \
  --workload-identity-pool=github-pool \
  --attribute-mapping="google.subject=assertion.sub,attribute.repository=assertion.repository" \
  --issuer-uri="https://token.actions.githubusercontent.com"

# Bind SA to GitHub repo (replace YOUR_GITHUB_ORG)
gcloud iam service-accounts add-iam-policy-binding \
  github-actions-deploy@$PROJECT_ID.iam.gserviceaccount.com \
  --project=$PROJECT_ID \
  --role="roles/iam.workloadIdentityUser" \
  --member="principalSet://iam.googleapis.com/projects/$PROJECT_NUMBER/locations/global/workloadIdentityPools/github-pool/attribute.repository/YOUR_GITHUB_ORG/mrd-producer-webapp"

# Get WIF provider name → save as WIF_PROVIDER in GitHub secrets
gcloud iam workload-identity-pools providers describe github-provider \
  --project=$PROJECT_ID --location=global \
  --workload-identity-pool=github-pool --format="value(name)"
ℹ After this, add 5 GitHub secrets: WIF_PROVIDER, WIF_SERVICE_ACCOUNT (github-actions-deploy@r-and-d-489319.iam.gserviceaccount.com), GCP_PROJECT_ID (r-and-d-489319), GCP_REGION (us-central1), GCP_ARTIFACT_REGISTRY (us-central1-docker.pkg.dev). The deploy.yml is already written and waiting.

Deploy to Cloud Run

10
Update Google OAuth client
Add Cloud Run URL as authorized redirect URI — required before testing login.
  1. Go to Google Cloud Console → APIs & Services → Credentials
  2. Click the OAuth 2.0 Client ID matching GOOGLE_CLIENT_ID
  3. Under Authorized redirect URIs, add:
    https://YOUR_CLOUDRUN_URL/api/auth/callback/google
  4. Keep the existing Vercel URI during transition — remove after cutover
  5. Save
⚠ If the OAuth client is under a personal account (not org GCP project), it must be re-created under the org project before go-live — otherwise login will break on the new domain.
