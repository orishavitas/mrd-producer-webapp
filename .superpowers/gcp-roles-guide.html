Search for ori@compulocks.com in the principals list. If the user already appears, click the pencil (edit) icon. If not, click Grant Access at the top and enter the email.
3
Add roles — Option A (recommended)
Add both roles below. This is the fastest path and covers all deployment needs.
roles/editor
Editor
Grants read and write access to all GCP services — creates Cloud Run services, Cloud SQL instances, Artifact Registry repositories, Secret Manager secrets, and more. Does not grant the ability to manage IAM itself.
Docs
roles/iam.securityAdmin
Security Admin
Grants the ability to get and set IAM policies. Required to create service accounts for GitHub Actions and bind them to Workload Identity Federation — neither of which Editor alone can do.
Docs
—
Add roles — Option B (least privilege)
Grant only the specific roles required. More secure, but more to configure.
roles/artifactregistry.admin
Artifact Registry Administrator
Create and manage Docker image repositories. Required to push the app's container image that Cloud Run will run.
Docs
roles/run.admin
Cloud Run Admin
Deploy, update, and manage Cloud Run services. Required to deploy the containerized Next.js app and configure traffic, secrets, and Cloud SQL connections.
Docs
roles/secretmanager.admin
Secret Manager Admin
Create and manage secrets (API keys, database credentials, OAuth secrets). All environment variables move from Vercel to Secret Manager during migration.
Docs
roles/cloudsql.admin
Cloud SQL Admin
Create and manage Cloud SQL instances and databases. Required to set up the PostgreSQL database that replaces Vercel Postgres.
Docs
roles/iam.serviceAccountAdmin
Service Account Admin
Create and manage service accounts. Required to create the dedicated GitHub Actions service account used to deploy from CI/CD to Cloud Run.
Docs
roles/iam.workloadIdentityPoolAdmin
Workload Identity Pool Admin
Create and manage Workload Identity Federation pools and providers. Required to set up keyless authentication between GitHub Actions and GCP — eliminates the need to store long-lived service account keys in GitHub secrets.
Docs
roles/resourcemanager.projectIamAdmin
Project IAM Admin
Grant IAM roles to service accounts within this project. Required to give the GitHub Actions service account the roles it needs (Cloud Run Admin, Artifact Registry Writer) and to grant Cloud Run access to Secret Manager and Cloud SQL.
Docs
4
Save and verify
Click Save in the console. IAM changes propagate within ~60 seconds. To verify from the terminal:
# Verify the roles were granted gcloud projects get-iam-policy r-and-d-489319 \ --flatten="bindings[].members" \ --format="table(bindings.role,bindings.members)" \ --filter="bindings.members:ori@compulocks.com"
